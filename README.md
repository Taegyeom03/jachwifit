# 자취핏 · 자취생을 위한 칼로리 플래너

> **바로 써 보기: https://jachwifit.netlify.app** (로그인 없이 바로 쓸 수 있고, 이메일로 가입하면 휴대폰 · PC에서 같은 기록을 볼 수 있어요)

자취생이 **돈을 적게 쓰면서 건강하게 살을 빼도록** 돕는 웹 앱입니다.
키와 몸무게를 넣으면 하루에 얼마나 먹으면 되는지 계산해 주고, 먹은 음식을 기록하면
**남은 칼로리 안에서 부족한 단백질을 가장 싸게 채우는 메뉴**를 양과 가격까지 알려 줍니다.

> 예: 단백질이 112g 부족하고 1,896kcal가 남았다면
> → "고등어캔 ×2 + 마른 멸치 ×2 + 계란 ×2 · 단백질 78g · 572kcal · 약 4,100원"

## 1. 이런 분께 맞아요

- 다이어트 중인데 **하루에 몇 kcal를 먹어야 하는지** 모르는 분
- 단백질이 부족한 건 알지만 **무엇을 얼마나 더 먹어야 하는지** 모르는 분
- 식비가 빠듯해서 **싸고 구하기 쉬운 음식**으로 채우고 싶은 분
- 치팅데이나 야식 때문에 **계획이 한 번 무너지면 포기하게 되는** 분

### 오늘 화면의 버튼들

- **자주 먹는 음식 · 📋 지난 식단 그대로 넣기:** 검색칸 위에 최근 30일 동안 자주 먹은 음식이 버튼으로 나와 한 번에 고를 수 있어요. 오늘이 비어 있으면 가장 최근에 기록한 날의 식단을 통째로 넣는 버튼도 나와요(같은 메뉴를 반복하는 자취생용).
- **✍️ 문장으로 기록 (AI, 로그인 필요):** "점심에 학식 제육덮밥, 저녁엔 닭가슴살 200g이랑 밥 반 공기"처럼 적으면 AI가 자취핏 음식 목록에서 음식 · 양 · 끼니를 찾아 **미리보기**로 보여 줘요. 체크한 것만 기록돼요. 목록에 없는 음식은 "못 찾은 것"으로 알려 주니 검색으로 직접 골라요. 하루 20번까지, 200자까지 쓸 수 있고, 문장은 음식을 찾는 데만 쓰고 저장하지 않아요.
- **추천 카드:** 남은 칼로리를 넘지 않으면서 부족한 단백질을 가장 싸게 채우는 조합 3개. 음식마다 영양 · 가격 출처와 기준일이 적혀 있어요.
- **[🌙 야식 먹고 싶어]:** 남은 칼로리 안에서 **🏪 편의점 · 🛵 배달/외식 · 🍳 집에서 간단히** 곳마다 가장 싼 조합을 하나씩 보여 줘요(치팅데이에는 치킨 · 족발도). 단백질을 이미 채웠으면 가벼운 야식 목록을, 남은 칼로리가 100kcal 미만이면 초저칼로리 메뉴만 보여 줘요.
- **직접 만들어 먹기:** 추천 카드 아래에 오늘 남은 칼로리 안에서 만들 수 있는 레시피 2개(단백질 많은 순)가 나와요. 누르면 레시피 화면으로 가요.
- **내가 산 가격 입력:** 음식을 검색해 고르면 바로 아래에 그 음식의 1회 가격과 출처가 나와요. [내가 산 가격 입력]으로 그 자리에서 가격을 바꿀 수 있어요.
- **⚖️ 오늘 몸무게:** 그날 잰 몸무게를 0.1kg 단위로 저장해요(비우고 저장하면 지워져요). 저장한 몸무게는 **내 계획** 화면의 그래프에 점으로 찍히고, 로그인했으면 다른 기기에도 보여요. 계획 선은 목표를 저장한 날부터 시작하고, 체중 · 목표 체중 · 감량 속도를 바꾸면 그날부터 새로 시작해요.
- **치팅데이 체크:** 그날 칼로리 상한을 유지 칼로리(TDEE)까지 올려요. 무제한은 아니고, 단백질 목표는 그대로예요. 추천에 치킨 · 족발 같은 메뉴도 들어가요. 이번 주에 목표보다 많이 먹었으면 남은 날 하루에 얼마나 줄이면 되는지 **안내만** 해요(굶으라고 하지 않아요).

## 4. 숫자는 어떻게 계산하나요?

계산과 추천은 **AI 없이 정해진 규칙**으로 해요. 목표 화면에서 내 숫자가 들어간 계산 과정을 그대로 볼 수 있어요.

| 무엇 | 계산 |
|---|---|
| 기초대사량 (BMR) | Mifflin-St Jeor 공식. 남: 10×체중 + 6.25×키 − 5×나이 + 5 / 여: 같은 식 − 161 |
| 하루 소비 칼로리 (TDEE) | BMR × 활동계수 (1.2 ~ 1.9, 5단계) |
| **하루 목표 칼로리** | TDEE − (주당 감량 kg × 7,700 ÷ 7). 단, **BMR보다 낮아지지 않게** 맞춤 |
| **하루 목표 단백질** | 현재 체중 × 1.2~1.6g (기본 1.4g) |
| 지방 · 탄수화물 | 지방은 목표 칼로리의 25%, 남은 칼로리는 탄수화물 |
| 식이섬유 | 성별 · 나이별 충분섭취량 (2025 한국인 영양소 섭취기준) |
| 예상 기간 | 뺄 체중 × 7,700kcal ÷ (하루 적자 × 7) → 주 단위 |

**경고가 뜨는 경우:** 주당 1kg 감량, 기초대사량 하한이 적용됨, 목표 체중이 저체중(BMI 18.5 미만), 단백질 · 탄수화물이 권장 에너지 비율(탄수화물 50~65%, 단백질 10~20%, 지방 15~30%)을 벗어남.

**추천 방식:** 단백질 1g당 가격이 싼 음식부터 담아요. 100kcal당 단백질 7g 이상인 음식을 먼저 쓰고, 부족분을 넘게 채우면 비싼 음식부터 덜어 내요. 시작 음식을 바꿔 서로 다른 조합 3개를 만들어요.

**레시피 칼로리 · 재료비:** 재료를 음식 데이터의 음식으로 적어 두고, 재료 양 × 1회 제공량 값으로 더해요. 식용유 · 소금 · 후추는 빠져 있어요(식용유 1작은술 약 40kcal). 내 가격을 넣었으면 재료비도 그 가격으로 계산해요.

**하루 식단 예시:** 끼니마다 밥 한 공기를 두고, 남은 칼로리로 단백질 반찬을 위 방식으로 채운 뒤, 그래도 남는 칼로리는 밥 반 공기 단위로 채워요. 목표보다 너무 적게 먹으면 근손실 · 요요 위험이 있어서예요.

## 5. 꼭 알아 둘 점

- **로그인하지 않으면 기록은 지금 쓰는 브라우저에만 저장돼요.** 휴대폰과 PC의 기록이 서로 공유되지 않고, 브라우저 데이터를 지우거나 시크릿 모드로 쓰면 사라져요.
- **로그인하면 목표 · 기록 · 내 가격이 계정에 저장돼요.** 휴대폰 · PC 어디서든 같은 계정으로 로그인하면 같은 내용이 보여요. 앱을 열거나 다시 돌아올 때 계정과 맞추고, 두 기기에서 같은 날을 고쳤으면 **더 나중에 고친 쪽**이 남아요.
- **로그아웃하면 그 기기의 기록은 지워져요**(계정에는 남아요). 같이 쓰는 기기라면 꼭 로그아웃하세요. 회원 탈퇴는 [내 계정]에서 할 수 있고, 계정과 모든 기록이 바로 지워져요.
- 비밀번호를 잊으면 로그인 화면의 **[비밀번호를 잊었어요]**로 재설정 메일을 받아요. (메일이 늦거나 스팸함에 들어갈 수 있어요.)
- **가격 중 일부는 임시값이에요.** 공공데이터에 없는 닭가슴살 제품 · 편의점 상품 · 외식 메뉴 등은 화면에 "가격 임시값"으로 표시돼요. **[가격] 메뉴에서 내가 산 가격을 넣으면** 추천 · 식비 · 식단 예시가 모두 그 가격으로 바뀌어요("가격 내가 입력"으로 표시). 내 가격도 이 브라우저에만 저장되고, 이미 적은 기록의 식비도 새 가격으로 다시 계산돼요.
- **[문장으로 기록]은 AI라 틀릴 수 있어요.** 미리보기에서 확인하고 체크한 것만 기록돼요. 적은 문장은 음식을 찾는 데만 OpenRouter(AI 중계 서비스)로 보내고 저장하지 않아요.
- **의료 조언이 아니에요.** 일반적인 추정치예요. 질환이 있거나 임신 중이라면 전문가와 상담하세요.

### 7.4 음식 데이터 고치기 · 다시 만들기

**값 하나만 고칠 때:** `data/foods.csv`를 직접 고치고 `npm run foods`를 실행하면 돼요. 가격을 고쳤다면 `price_source` · `price_date`도 같이 고쳐 주세요. 새 음식은 **맨 뒤에** 붙여야 해요(앞에 넣으면 음식 번호가 바뀌어 기존 기록이 다른 음식을 가리켜요).

**칸 설명 (`data/foods.csv`)**

| 칸 | 뜻 |
|---|---|
| `name` · `serving_label` · `serving_g` | 이름 · 1회 제공량 표시(예: 1공기(210g)) · 1회 제공량 g |
| `kcal` · `protein` · `carb` · `fat` · `fiber` | 1회 제공량당 영양 |
| `price` · `price_source` · `price_date` | 1회 제공량 가격(원) · 출처(임시값이면 "임시값") · 기준일 |
| `nutrition_source` · `nutrition_date` | 영양 출처 · 기준일 |
| `tags` | `원재료` · `편의점` · `간단조리` · `야식` · `치팅` (`\|`로 구분). 야식 추천 · 치팅데이 후보에 쓰여요 |

**공공데이터로 영양 정보 다시 만들기**

```bash
node scripts/fetch-public-data.mjs ../public-data     # 공공데이터포털 파일 받기 (약 120MB, 저장소에 넣지 않음)
node scripts/match-public-data.mjs ../public-data     # 음식별 규칙(RULES)대로 찾아 data/foods.csv 갱신
```

파일에 없는 음식은 식약처 **Open API**로 채워요. [공공데이터포털](https://www.data.go.kr/data/15127578/openapi.do)에서「식품의약품안전처_식품영양성분DB정보」를 활용신청(개발계정 자동승인)하고, 마이페이지의 **일반 인증키(Decoding)**를 `.env.local`에 넣어요.

```bash
# .env.local (git에 올라가지 않아요)
DATA_GO_KR_KEY=발급받은키
```

```bash
node scripts/fetch-nutrition-api.mjs           # 찾은 제품과 바뀔 값 미리보기 (파일은 안 바뀜)
node scripts/fetch-nutrition-api.mjs --write   # data/foods.csv 갱신
```

- 새 음식을 API로 추가하려면 `scripts/fetch-nutrition-api.mjs`의 `RULES`에 `add`(제공량 · 가격 · 태그)와 `code`(식품코드) 또는 검색어를 넣어요. `match-public-data.mjs`의 `RULES`에도 같은 이름을 `keepTemp`로 넣어야 다시 돌려도 API 값이 유지돼요.

**공공데이터로 가격 다시 만들기**

KAMIS 인증키는 [kamis.or.kr](https://www.kamis.or.kr) Open API에서 무료로 발급받아요.

```bash
KAMIS_CERT_KEY=발급키 KAMIS_CERT_ID=발급ID node scripts/fetch-public-prices.mjs ../public-prices   # KAMIS 당일 + 참가격 최신 월
node scripts/match-public-prices.mjs ../public-prices                                              # 음식별 규칙대로 가격 갱신
```

음식별 상품과 환산 비율은 `scripts/match-public-prices.mjs`의 `RULES`에 있어요.

> 키는 어떤 것도 저장소에 넣지 않아요. `.env*` 파일은 `.gitignore`에 들어 있어요.

### 7.5 레시피 추가하기

`data/recipes.json`에 하나를 더 넣으면 돼요. 재료의 `food`는 `data/foods.csv`의 음식 이름과 **똑같이** 쓰고, `amount`는 1회 제공량의 몇 배인지 적어요(예: 양배추 1회(100g)을 150g 쓰면 1.5). `tool`은 `전자레인지` · `프라이팬` · `불 없이` · `냄비` 중 하나예요. 식용유를 쓰면 `"oil": true`, 주의할 점은 `note`에 적어요. 이름이 틀린 재료가 있으면 그 레시피는 화면에 나오지 않고 개발 서버 콘솔에 경고가 떠요.

### 7.6 계정 기능 (Supabase) 설정

1. [supabase.com](https://supabase.com)에서 프로젝트를 만들어요 (Region: Northeast Asia (Seoul)).
2. **SQL Editor**에 `supabase/schema.sql`을 통째로 붙여 넣고 **Run**. 표 `user_state`(목표 · 내 가격) · `day_logs`(날짜별 기록), 본인 데이터만 읽고 쓰는 보안 규칙(RLS), 탈퇴 함수가 만들어져요.
3. **Authentication → Sign In / Providers → Email**: Confirm email을 **끄기** (무료 메일 발송 한도 때문에 켜 두면 가입이 막힐 수 있어요).
4. **Authentication → URL Configuration**: Site URL에 배포 주소, **Redirect URLs**에 `https://배포주소/reset` (비밀번호 재설정 메일 링크가 돌아올 주소. 빠뜨려도 첫 화면으로 돌아온 뒤 재설정 화면으로 옮겨 줘요).
5. **Project Settings → API Keys**의 Project URL과 **publishable(anon) 키**를 `.env.local`과 Netlify 환경변수에 넣어요. **secret / service_role 키는 절대 넣지 않아요.**

```bash
NEXT_PUBLIC_SUPABASE_URL=https://프로젝트.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...
```

publishable 키는 브라우저에 공개되는 키예요. 데이터는 보안 규칙(RLS)으로 로그인한 본인 것만 읽고 쓸 수 있어요.

6. **추가 SQL(마이그레이션)**: `supabase/migrations/` 안의 파일을 번호 순서대로 SQL Editor에서 실행해요. 여러 번 실행해도 안전해요.
   - `002_checks_and_ai_quota.sql`: 서버 쪽 입력 검사(날짜 범위 · 기록 형식 · 크기 제한)와 AI 하루 호출 횟수 함수(`ai_take_quota`). **이걸 실행해야 [문장으로 기록]이 켜져요.**

#### 개발용 DB 따로 쓰기 (개발 · 운영 분리)

내 컴퓨터에서 테스트하다 실제 사용자 데이터(운영 DB)를 건드리지 않도록, 개발용 Supabase 프로젝트를 하나 더 만들어 쓰는 걸 권장해요. 코드 수정은 필요 없어요.

1. Supabase에서 프로젝트를 하나 더 만들어요 (예: `jachwifit-dev`). 위 1~3, 6번을 똑같이 해요.
2. 프로젝트 폴더에 `.env.development.local` 파일을 만들고 **개발용** 주소와 publishable 키를 넣어요.
   ```bash
   NEXT_PUBLIC_SUPABASE_URL=https://개발용프로젝트.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...
   ```
3. `npm run dev`는 `.env.development.local`을 `.env.local`보다 먼저 읽어서 개발용 DB에 붙고, Netlify 배포(운영)는 Netlify 환경변수의 운영 DB를 그대로 써요.

### 7.6.1 AI 기능 (문장으로 기록) 설정

AI는 [OpenRouter](https://openrouter.ai)를 거쳐 부르고, **서버(`app/api/parse-meal`)에서만** 호출해요. 키는 브라우저로 나가지 않아요.

1. OpenRouter에서 **Keys → Create Key**. 만들 때 **Credit limit(사용 한도)**을 1~2달러 정도로 걸어 두세요.
2. `.env.local`과 Netlify 환경변수에 넣어요. **`NEXT_PUBLIC_`을 붙이지 않아요.**
   ```bash
   OPENROUTER_API_KEY=sk-or-...
   # 선택: 모델 (기본 anthropic/claude-haiku-5.5), 하루 사용자당 호출 수 (기본 20)
   OPENROUTER_MODEL=
   AI_DAILY_LIMIT=
   ```
3. 위 6번의 `002_checks_and_ai_quota.sql`을 실행해요.

키나 DB 함수가 없으면 AI 기록 칸은 "준비 중이에요"라고 안내하고 꺼져 있어요. 나머지 기능은 그대로 동작해요.

**안전장치:** 로그인한 사용자만 · 하루 20번 · 200자 · JSON 스키마로 받은 응답을 서버에서 다시 검사(없는 음식 id · 1회 제공량 10배 · 2kg 넘는 양은 버림) · 429/5xx는 1·2·4초 간격 최대 3번 재시도 · 전체 9초 제한(Netlify 함수 10초 안) · 형식이 틀리면 한 번 재요청 · AI 쪽 문제로 실패하면 쓴 횟수를 돌려줌 · 결과는 미리보기에서 사용자가 고른 것만 저장 · 문장 속 지시는 따르지 않도록 프롬프트를 서버에 고정.

**모델 비교:** 키를 넣은 뒤 `npm run eval:models` → 모델 3개(Claude Haiku · GPT-5 nano · Gemini Flash-Lite)를 같은 테스트 세트로 채점해 통과 수 · 응답 시간 · 1회 비용 · 한 달 예상 비용을 `reports/model-compare.md`에 표로 남겨요. 다른 모델은 `npm run eval:models -- 모델id 모델id`.

**데이터 품질 리포트:** `npm run data:quality` → `reports/data-quality.md` (빈 칸 · 형식 · 출처 비율 · 열량 검산 · 범위 확인).

**추천 실험 (그리디 vs 최적해):** `npm run experiment:recommend` → `reports/greedy-vs-optimal.md`. AI 키가 필요 없어요.

**테스트 세트 채점:** `data/ai-test-set.json`에 입력 · 기대 결과 · 판정 기준 10개(경계 · 공격 입력 포함)가 있어요. 키를 넣은 뒤 아래를 실행하면 실제 AI로 채점하고 결과를 `reports/ai-eval-latest.md`에 남겨요(한 번에 약 10번 호출).

npm run eval:ai

- **가격은 시장 소매가 기준이에요.** KAMIS는 원재료 소매가라 편의점 · 온라인 가격과 다를 수 있고, 일부는 임시값이에요. → [내 가격]으로 직접 고칠 수 있게 해 두었어요.
- **추천이 최적은 아니에요.** 단백질 1g당 가격 순 그리디라 멸치 · 계란 · 고등어캔이 자주 나오고, 나트륨은 따지지 않아요. 모든 조합을 따지는 최적해와 36가지 상황을 비교한 결과는 [reports/greedy-vs-optimal.md](reports/greedy-vs-optimal.md)에 있어요 (`npm run experiment:recommend`). → 다양성 · 나트륨 상한 추가
- **계정:** 소셜(카카오 · 구글) 로그인이 없어요. 비밀번호 재설정은 메일로 할 수 있지만, Supabase 기본 메일은 시간당 보낼 수 있는 수가 적어요.

- **AI 기록:** AI가 틀릴 수 있어 항상 미리보기에서 확인 후 저장해요. 테스트 세트 10개로만 검증했어요.
- **검증:** 실제 사용자 테스트로 성공 지표(7일 연속 기록 · 단백질 80% 충족)를 아직 재지 않았어요.

## 10. 용어 정리

| 용어 | 뜻 |
|---|---|
| 기초대사량 (BMR) | 가만히 있어도 하루에 쓰는 최소 칼로리. 이보다 적게 먹으면 몸에 무리가 가요 |
| 하루 소비 칼로리 (TDEE) | 활동까지 포함해 하루에 실제로 쓰는 칼로리 = 유지 칼로리 |
| 하루 적자 | TDEE − 목표 칼로리. 7,700kcal가 쌓이면 약 1kg이 빠진다고 봐요 |
| 1회 제공량 | 한 번에 먹는 기준 양 (예: 계란 1개, 공기밥 1공기 210g) |
| 임시값 | 공공데이터에 없어 대략 넣어 둔 값. 화면에 "임시값"으로 표시돼요 |
| 내 가격 | 내가 실제로 산 가격. [가격] 메뉴나 음식을 고를 때 입력하고, 화면에 "가격 내가 입력"으로 표시돼요 |
| 동기화 | 이 기기에 저장한 내용과 계정(서버)에 저장한 내용을 맞추는 것. 같은 날을 두 기기에서 고쳤으면 더 나중에 고친 쪽이 남아요 |
| 치팅데이 | 그날만 칼로리 상한을 유지 칼로리까지 올리는 날 (단백질 목표는 유지) |
| 성공 지표 | 최근 7일 기록 일수, 추천이 남은 칼로리를 넘은 건수, 단백질 부족분 평균 충족률(목표 80%) |
